運作方式

從提問到有出處的答案，四個步驟

Agent 自己決定要查知識庫、統計記錄、上網搜尋或呼叫 API，每一步都記在研究過程裡；會改動外部系統的工具，執行前先問你。

混合檢索

兩軌檢索，依名次融合，重排機率把關

向量與 BM25 每次都跑，以 RRF 依名次融合，再由 Cross-Encoder 重排。重排機率低於門檻的片段一律濾除，全部沒過就回報查無資料，不拿無關片段硬答。

        安全

        三輪安全稽核，防護是預設路徑

        工具結果一律當成不可信資料，web_fetch 只讀使用者訊息或本次工具結果中原樣出現過的網址，出站請求逐跳驗證並把連線固定在核可的 IP。

        1. 協定只允許 http、https
        2. 帳號密碼網址不得含帳號密碼
        3. 連接埠擋下資料庫、快取與遠端管理服務
        4. 主機名稱擋下保留名稱與內部網域後綴
        5. IP 網段擋下私有、迴環、連結本地與保留網段
        6. DNS 與固定 IP伺服器端執行
        7. 逐跳轉址伺服器端執行

        • 權杖對應資料庫帳號

          RSA-2048 簽署 JWT，每次請求都以帳號目前的狀態與權限為準；變更密碼或停用帳號，先前的權杖一律失效。

        • 登入失敗節流

          Argon2 雜湊密碼；同一帳號或來源位址失敗達門檻就暫停登入，回傳 429 與 Retry-After。

        • 工具憑證加密存放

          API 工具與 MCP 的標頭、金鑰以 Fernet 加密寫入資料庫，管理 API 只回 ••••••••。

        • 工具結果是不可信資料

          每次提問以不同 id 的 untrusted_tool_result 標記包住結果，文件或網頁夾帶的指令不會被執行。

        • 每個入口都有上限

          單則訊息 20,000 字、附件 5 個、每人同時 2 個回答串流，超過就回 413、422 或 429。

        • 錯誤只回代碼

          未預期的例外只對外回隨機錯誤代碼，堆疊寫進伺服器日誌；日誌雙層遮蔽，權杖顯示為 [REDACTED]。

        快速開始

        三個步驟，在本機跑起來

        需要 Python 3.12 以上與 Bun 1.x；預設用 SQLite，不需另裝資料庫。首次啟動會下載約 1.2 GB 的嵌入與重排模型。

        1. 1

          取得原始碼

          git clone https://github.com/Scorpio-meow/AskMiao.git
cd AskMiao

        2. 2

          設定並啟動後端

          cd backend
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python main.py

          啟動前在 .env 把 DATABASE_URL 改成 sqlite:///./chatbot.db，並換上自己產生的 TOOL_SECRETS_KEY。

        3. 3

          啟動前端，建立管理員

          cd frontend
bun install
bun run dev

          在 backend/ 執行 python scripts/create_user.py --username admin --email admin@example.com --admin，再開啟 http://localhost:3000 登入。
