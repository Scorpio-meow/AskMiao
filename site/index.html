工具憑證加密存放，寫入後就讀不出來

  • 可以關閉自行註冊

  • 只接受宣告過的參數

    沒在 parameters_schema 宣告的參數，工具直接回 400「工具參數無效」；網址中寫死的查詢參數不能被覆寫。

    不再安裝有 CVE-2024-33663 與 CVE-2024-23342 的 python-jose、ecdsa；解碼只接受 RS256，簽發時間在未來的權杖也會被拒絕。

  • 建置產物帶 CSP

    bun run build 把 CSP 寫進 index.html：腳本只允許建置產物與內嵌腳本的雜湊，被注入的 HTML 也無法執行腳本。

    CWE-79

  • 相依套件以雜湊鎖定

    requirements.txt 由 uv pip compile --generate-hashes 產生並在安裝時驗證；bun.lock 納入版本控制，安裝時不可變更。

    CWE-1357、CWE-494

  • PostgreSQL 改用非超級使用者

    後端以 POSTGRES_APP_USER 連線，就算出現 SQL 注入，也無法以 COPY … TO PROGRAM 執行系統指令或讀取伺服器檔案。

    CWE-250

  • 聊天附件有解析預算

    docx 與 pptx 會建成 DOM 的 XML 最多 8 MiB、解壓總量 64 MiB、成員 10,000 個，整個行程同時最多解析 2 個附件。

    CWE-409、CWE-400

  • 不安全的預設值改為必填

    HOST、RELOAD、COOKIE_SECURE、ENABLE_API_DOCS 都要明確設定，互動式 API 文件預設不提供。

    CWE-1188

  • 長字串不再凍結聊天頁

    自動連結轉換先以線性時間估算掃描量，5 萬字元的一長串句點從 2.6 秒降到 0.03 秒。

    CWE-1333

從 4.0.0 升級前要做的事

不需要重建索引，新欄位與憑證加密在啟動時自動完成。需要動手的是設定、套件、資料庫帳號與工具宣告。

完整升級步驟與回退方式
  1. 停止後端，備份資料庫、backend/data/、backend/keys/ 與 .env。
  2. 在新的虛擬環境依鎖定雜湊的 requirements.txt 安裝，前端執行 bun install。
  3. .env 補上 10 項必填設定，自行產生 TOOL_SECRETS_KEY，並與資料庫備份一起保存。
  4. 使用 compose 的 PostgreSQL 時，設定 POSTGRES_APP_USER、POSTGRES_APP_PASSWORD，執行一次 20-app-role.sh，DATABASE_URL 改用新帳號。
  5. 關閉註冊時，以 scripts/create_user.py 建立帳號；檢查每個自訂 API 工具的參數宣告與 stdio MCP 的相對路徑。
  6. 重新執行 bun run build，讓 CSP 寫進建置產物。

NIST 最新版對密碼更換週期怎麼建議？我們公司的資安政策需要修改嗎？

結論

NIST SP 800-63B-4 已不要求定期更換密碼，只有出現外洩跡象時才強制更換。公司《資訊安全管理政策 v3.2》仍規定一般帳號每 90 天、特權帳號每 60 天更換，兩者確實不同。

帳號連續登入失敗 5 次會鎖定 30 分鐘，與 NIST 限制連續失敗次數的要求一致。

建議

下次修訂可考慮取消一般帳號的定期更換，改為比對外洩密碼清單，並保留特權帳號的多因子驗證。

        哪些工具預設需要核准？

        管理員建立工具時可以改動「需要核准」核取方塊；下面是沒有特別設定時的預設值。

        • 內建工具 不需要 search_knowledge_base、filter_and_count_records、web_search、web_fetch 只讀取資料，由網址來源與 SSRF 規則把關。
        • 自訂 API 工具 依 HTTP 方法 GET、HEAD、OPTIONS 以外的方法預設需要核准；升級到 4.0.0 時，既有工具依方法自動回填。
        • MCP 伺服器 需要 以伺服器為單位設定，整台伺服器的工具一起套用；卡片上的名稱顯示為「伺服器 → 工具」。

        只有發問者能核准

        每個待核准項目綁定建立它的使用者。別人拿到 approval_id 也無法代為核准，端點一律回傳 404。

        300 秒沒回應就是拒絕

        逾時送出 approval_resolved（approved 為 false），模型收到「使用者未核准」，並被要求不要再呼叫同一工具。

        沒有人能核准，就不執行

        不是由使用者在對話中發起的 Agent 呼叫，這類工具一律回傳錯誤，改以已取得的資料回答。設計背景見 ADR-0006。

        安全不是附加功能，而是預設路徑

        工具結果、出站請求、工具管理、認證、資源用量與日誌，每條路徑都有對應的防護模組與測試。專案做過兩輪安全稽核：4.0.0 處理第一輪的 52 項線索，5.0.0 修正第二輪的發現。

        工具只有管理員能管，子行程拿不到金鑰

        stdio 類型的 MCP 伺服器會在主機上執行指令，所以 /api/mcp 與 /api/api-tools 的所有端點（含查詢）都只開放管理員，一般使用者一律 403。子行程也只繼承系統必要變數：

        DATABASE_URL有不傳入

        每一跳驗證，連線固定 IP

        自訂 API 工具、MCP HTTP 傳輸與 web_fetch 每一跳都重跑 SSRF 檢查，並直接連到驗證時核可的 IP；DNS rebinding 無法在驗證與連線之間換掉目標，TLS 仍以原主機名稱驗證憑證。

        權杖對應資料庫帳號

        以 PyJWT 簽署與驗證 RS256，缺金鑰就拒絕啟動。每次請求依 sub 讀取帳號，停用、刪除、降權或變更密碼立即生效；Refresh Token 存於 HttpOnly Cookie，換發一次就撤銷。

        雙層日誌脫敏

        物件層遞迴遮罩 password、token、authorization 等欄位，序列化前再以正則二次遮罩；單一欄位最多 200 字元，日誌以 10 MiB × 5 份輪替。

        錯誤只回代碼

        未預期例外只回傳 12 碼 error_id，完整堆疊留在伺服器日誌，SSE 串流同樣不夾帶例外文字（CWE-209、CWE-497）。

        每個入口都有上限

        一個使用者、一份檔案或一次工具回應，都不該拖垮整個後端或燒掉操作者的模型額度。上限集中定義在 backend/app/core/limits.py，超過時回傳明確的狀態碼。

        每天都要用的介面，細節要到位

        串流、鍵盤、讀螢幕軟體、手機與深色模式都重新整理過；每個操作都有回饋，不會默默失敗。

        • 停止產生、失敗重送

          串流中隨時停止，停止的回答不會儲存；失敗時顯示原因並可重新傳送。

        • 淺色、深色、跟隨系統

          在帳號選單切換，第一次繪製前就套用，深色模式不再先閃白。

        • 注音、倉頡不誤送

          用輸入法按 Enter 選字時，不會把還沒打完的訊息送出。

        • 鍵盤與讀螢幕軟體

          焦點清楚可見、欄位標籤綁定輸入框，回答完成、失敗或停止都會播報。

        • 刪除前先確認

          對話、使用者、文件、工具與 MCP 伺服器，刪除前都會以原生對話框確認。

        • 離線與恢復提示

          網路中斷與恢復都有提示；SSE 事件被網路切成兩段也不會遺失。

        • 手機版重新排版

          單列 64px 頂欄、聊天頁固定一個視窗高度，輸入框 16px，iPhone 聚焦時不再放大。

        • 回到最新訊息

          往上翻閱舊訊息時不會被拉回底部，需要時一鍵回到最新。

        三個步驟，本機跑起來

        預設使用 SQLite，不需要 Docker、PostgreSQL 或 Redis。環境需求：Python 3.10 以上、Bun 1.0 以上。

        1. 複製儲存庫

          取得原始碼並進入專案目錄。

          git clone https://github.com/Scorpio-meow/AskMiao.git
cd AskMiao

        2. 啟動後端

          建立虛擬環境、安裝依賴後啟動 FastAPI（8001 埠），資料表會在第一次啟動時自動建立。第一次啟動也會下載嵌入與重排模型（約 1.2 GB）；重排模型是必要元件，載入失敗時後端不會啟動。

          先改 .env：.env.example 的 DATABASE_URL 指向 PostgreSQL，零依賴啟動請改成 sqlite:///./chatbot.db，並把 ADMIN_API_KEY 換成隨機字串。TOOL_SECRETS_KEY 必須換成自行產生的 Fernet 金鑰（程式碼中的 py -c 指令會印出一組），範本值不是有效的金鑰，沒換掉時後端不會啟動。LLM 提供商金鑰擇一設定即可。JWT 一律以 backend/keys/ 的 RSA 金鑰簽署，第一次啟動自動產生，該目錄須可寫入。 
          cd backend
py -m venv .venv
# Windows PowerShell；Linux / macOS 改用 source .venv/bin/activate
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
cp .env.example .env
# 印出一組 Fernet 金鑰，填入 .env 的 TOOL_SECRETS_KEY
py -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
py main.py

        3. 啟動前端

          以 Bun 安裝依賴並啟動 Vite 開發伺服器，開啟 http://localhost:3000 即可登入；若沿用 frontend/.env.example 的 PORT=3001，則改為 3001。

          第一位管理員：系統不會預先建立管理員，範本的 ALLOW_REGISTRATION=false 也不開放自行註冊。請在 backend/ 啟用虛擬環境後執行 py scripts/create_user.py --username admin --email admin@example.com --admin，依提示輸入兩次密碼，再以這組帳號登入，才看得到知識庫與 AI 工具。其他帳號同樣以這個腳本建立，說明見 README。
          只接受本機連線：Vite 開發與預覽伺服器只監聽 localhost。要讓區網裝置使用，請以 bun run build 建置，再由正式的網頁伺服器提供 frontend/build/ 並反向代理 /api。 
          cd ../frontend
bun install
bun run dev
