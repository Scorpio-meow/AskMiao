# ADR-0002: 外部工具擴充機制與出站請求安全防護決策

[繁體中文](0002-external-tools-and-outbound-safety.md) | [English](0002-external-tools-and-outbound-safety_en.md)

## 狀態

已通過 (Accepted) - 2026-09-01

---

## 背景與問題陳述

Agentic RAG 管線上線後，內建工具（知識庫檢索、統計篩選、聯網搜尋、網頁抓取）已無法涵蓋企業實際需求：

1. **工具擴充成本過高**：每接入一個外部系統（工單、簽核、庫存查詢）都需修改 `rag/tools.py` 並重新部署後端，導入週期長且與版本綁定。
2. **生態整合需求**：MCP（Model Context Protocol）已成為工具伺服器之通用協定，若能直接接入既有 MCP 伺服器，可免去逐一封裝之成本。
3. **出站請求形成新攻擊面**：一旦允許使用者自行指定 URL（OpenAPI 規格來源、API 端點、遠端 MCP 伺服器），伺服器即可能被誘導對內網位址或雲端中繼資料端點發出請求（SSRF）。
4. **例外訊息外洩風險**：外部呼叫失敗之例外常夾帶內部路徑、主機名稱與堆疊，直接回傳前端將洩漏系統結構。

---

## 架構決策內容

### 1. 以資料庫驅動之工具註冊（而非程式碼註冊）

- 新增 `custom_api_tools` 與 `mcp_servers` 兩張資料表，分別存放自訂 HTTP API 工具與 MCP 伺服器設定（含 `discovered_tools` 工具快取）。
- `ResearchToolRegistry.get_tool_definitions()` 於每次組裝工具定義時查詢啟用中的紀錄並合併至工具集，使工具異動即時生效，無需重啟後端。
- MCP 工具統一採 `mcp_<伺服器名稱>_<工具名稱>` 命名慣例，`execute_tool` 依前綴路由至 `McpManager.execute_mcp_tool`。

### 2. OpenAPI 規格匯入取代逐一手動設定

- 新增 `OpenApiParser` 支援 OAS 2.0 / 3.0 / 3.1，解析後由前端勾選端點批次匯入；同名工具採覆寫更新，維持可重複匯入之冪等性。
- 參數位置（`path` / `query` / `header` / `body`）以 `param_locations` 保存，由通用 HTTP 執行器於執行期組裝請求。

### 3. 集中式 SSRF 防護閘門

- 新增 `app/core/ssrf_protection.py`，所有由使用者輸入驅動之出站請求（OpenAPI 規格 URL、`web_fetch`、MCP HTTP 傳輸、自訂 API 工具）皆須先通過驗證。
- 驗證順序：協定 → 連接埠 → 主機名稱 → DNS 解析後之所有 IP 範圍；阻擋私有與保留網段、迴環與連結本地位址、雲端中繼資料端點與危險連接埠。

### 4. 統一錯誤代碼機制

- 新增 `app/core/error_response.py`，未預期例外僅回傳 12 碼隨機 `error_id`，完整訊息與堆疊留存於伺服器日誌（CWE-209 / CWE-497）。
- 以 `SafeClientError` 標記「僅描述使用者輸入本身」之驗證錯誤，使其可原樣回傳，兼顧可用性與安全性。

## 決定產生的影響與權衡

### 正面影響 (Benefits)

- **擴充成本大幅下降**：接入新系統由「改程式碼 + 部署」降為「貼上規格 + 勾選端點」。
- **生態相容**：可直接複用既有 MCP 伺服器，避免重複封裝。
- **攻擊面收斂**：出站請求集中於單一防護閘門，新增呼叫點只需接上同一驗證函式即可獲得相同保護。
- **資訊洩漏防範**：錯誤代碼機制同時涵蓋 REST 回應與 SSE 串流事件。

### 負面影響與挑戰 (Trade-offs & Risks)

- **工具定義組裝成本**：每次組裝工具定義皆需查詢資料庫；目前以 MCP 工具快取（`discovered_tools`）降低連線開銷，若工具數量大幅成長需再導入快取層。
- **憑證保管責任**：自訂工具之 API 金鑰存於資料庫（`auth_config`），需依部署環境施加加密或密鑰管理措施。
- **誤擋風險**：SSRF 防護會阻擋指向內網之合法內部 API；此類情境需於部署層明確開放，屬預期取捨。
- **除錯體驗**：對外僅有錯誤代碼，排查時須由伺服器日誌以 `error_id` 對應，對維運流程有額外要求。
