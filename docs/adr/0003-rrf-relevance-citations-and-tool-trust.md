# ADR-0003: RRF 融合、相關性門檻、引用對應與工具輸出信任邊界

[繁體中文](0003-rrf-relevance-citations-and-tool-trust.md) | [English](0003-rrf-relevance-citations-and-tool-trust_en.md)

## 狀態

已通過 (Accepted) - 2026-09-24

取代 [ADR-0001](./0001-hybrid-rag-and-security.md) 中「分數歸一化融合」的決策。

## 背景與問題陳述

1. **兩軌檢索名存實亡**：查詢先依寫死的規則分流（純英文只走 BM25、長中文句只走向量、含 FAQ 關鍵字才走混合），混合時再以 `HYBRID_ALPHA = 0.75` 加權正規化分數。只有 BM25 找到的片段即使排第一，加權後也會落在向量前 30 名之後，重排只取前段時完全進不去。
2. **門檻永遠放行**：門檻套在「0.85 × 重排分數 + 0.15 × 原分數」上，而第一名的原分數經正規化必為 1，就算重排判定完全無關也剛好拿到 0.15 過門檻，因此永遠至少塞一段給模型；重排失敗時更直接回傳未過濾的片段。
3. **來源標籤與答案無關**：來源標籤列出本次所有檢索結果（前 6 筆），不代表答案實際用到哪些資料。
4. **工具輸出沒有信任邊界**：工具結果原樣放進對話，文件或網頁內容可夾帶提示注入；模型也可能把知識庫或對話中的內部資料拼進 `web_fetch` 的網址外送。
5. **回應延遲**：用到工具的提問會丟掉模型已產生的答案再完整生成一次，並以「每 4 字停 15 毫秒」的假串流送出。
6. **斷詞與領域資料**：BM25 區分大小寫（查 `mes` 對不到 `MES`）；領域詞、記錄日期欄位與摘要備援規則寫死在程式裡。
7. **誤刪風險**：uploads watcher 在上傳檔不見時會刪除索引與資料庫紀錄，而設定中的相對路徑以啟動目錄為基準，從其他目錄啟動時所有文件都會被判為遺失。

## 架構決策內容

### 1. 標準 RRF，兩軌必跑

- 每次查詢向量與 BM25 各取 `TOP_K` 筆，以 Reciprocal Rank Fusion 依名次合併：分數 = Σ 1 / (`RRF_K` + 名次)，取前 `RERANK_TOP_K` 筆重排。
- 採**不加權**的標準 RRF，移除 `HYBRID_ALPHA`、`NORMALIZATION` 與 `auto_tune_alpha`。考慮過保留 alpha 的加權 RRF，但沿用 0.75 會重現第 1 點的問題（BM25 第一名排在向量前 30 名之後），而目前也沒有問答集可以校準權重。
- 網址、貼文 ID、日期、@帳號的精確比對結果另外加入候選並排在最前面。

### 2. 相關性門檻直接看重排機率

- 新增 `RERANK_RELEVANCE_THRESHOLD`（取代 `FINAL_THRESHOLD`），直接套在重排模型的機率上；混合分數只用於排序。
- 精確比對到網址、貼文 ID、日期的片段不受門檻限制（只有網址的查詢，重排分數本來就偏低）。
- 重排模型改為必要元件：載入失敗時後端無法啟動；執行時重排失敗則回傳錯誤代碼，不再回傳未過濾的片段。
- 沒有片段通過門檻時，`search_knowledge_base` 明確回傳「知識庫中查無相關資料」；指定 `target_document` 時在重排前就限定該文件，查不到也不改用全庫結果。
- 問答集允許 `"relevant_sources": []` 的反例；評估 CLI 以 `--relevance-thresholds` 對同一次重排結果比較多個門檻（正例 hit@k、MRR 與反例拒絕率）。

### 3. 引用對應來源

- 每次提問建立一張引用編號表：知識庫片段以 chunk_id、網頁以網址為鍵，第一次出現時配號並寫入工具結果，同一片段再出現沿用原號碼。
- 系統提示要求模型以 `[n]` 標註出處且只能用工具結果中的編號；答案完成後解析 `[n]`（支援 `[1,2]`、`[1][2]`），來源只列實際被引用的條目，依第一次引用的順序排列並去重。沒有任何引用時不顯示來源標籤。

### 4. 工具輸出信任邊界

- 所有工具結果包在每次提問 id 不同的 `<untrusted_tool_result>` 標記內，系統提示規定只當資料看、不照其中的指令做，也不把對話或知識庫內容拼進網址或搜尋字串。
- `web_fetch` 只能讀取使用者訊息或本次內建工具結果資料欄位中原樣出現過的網址。工具回聲的查詢參數不算來源，以免模型先把資料塞進查詢，再以「出現過」的網址外送。
- `WEB_FETCH_ALLOWED_DOMAINS` 為網域白名單（含子網域），明確寫 `*` 才表示不限制；`BLOCK_WEB_TOOLS_AFTER_KB` 開啟時，同一次提問只要知識庫工具回傳過內容，之後的聯網工具一律拒絕。

### 5. 其他連帶決策

- 模型不再呼叫工具時，該次內容即為最終答案，不再重新生成；移除假串流，只有工具輪數用完或模型回傳空內容時才以真串流生成。
- 斷詞結果一律轉小寫；可用 `JIEBA_DICTIONARY` 替換主詞典；BM25 索引目錄記錄斷詞簽章（規則版本、主詞典雜湊、領域詞雜湊），不符時自動重建 BM25，唯讀評估則拒絕執行。
- 領域詞、記錄日期欄位與摘要備援規則移至 `DOMAIN_PROFILE_PATH` 指定的設定檔（`backend/config/domain_profile.json`），啟動時驗證格式。
- 設定中的相對路徑一律以 `backend/` 為基準；uploads watcher 在檔案遺失時只記一次警告，不刪除索引或資料庫（文件內容本來就存在資料庫，重建索引時也會改用資料庫內容）。

## 決定產生的影響與權衡

### 正面影響 (Benefits)

- 只有單一軌道找到的片段也能進入重排候選，專有名詞與代碼查詢不再被加權淹沒。
- 離題問題會明確得到「查無資料」，不再永遠塞入無關片段；重排失敗時不會把未過濾的內容交給模型。
- 來源標籤與答案內容一一對應，使用者可以逐句核對出處。
- 提示注入無法藉由工具結果改寫規則，模型也無法把內部資料組進網址外送。
- 用到工具的提問少一次完整的 LLM 呼叫，也省下假串流的等待。

### 負面影響與挑戰 (Trade-offs & Risks)

- **重排延遲**：CPU 實測每對約 0.2 秒（300 字片段）至 0.4 秒（800 字片段），`RERANK_TOP_K = 20` 時每次知識庫檢索約 4 至 8 秒；精確比對候選沿用舊行為不受 `RERANK_TOP_K` 限制，日期或 @帳號一次比對到大量片段時成本會再增加。
- **門檻的召回風險**：小語料實測時，重排模型對換句話說（例如以「ChatGPT」查「生成式 AI 服務」）與單一關鍵字查詢給分偏低，正反例在 0.3 至 0.42 之間有重疊。`0.2` 只是暫定值，須以實際問答集的 `--relevance-thresholds` 結果校準。
- **串流體驗**：用到工具的答案會一次整段出現，而不是逐字跑出，但出現時間比原本早。
- **啟動條件更嚴格**：重排模型快取缺失或無法下載時後端無法啟動；新增的必填設定未加入 `.env` 時也會啟動失敗。
- **聯網限制**：啟用 `BLOCK_WEB_TOOLS_AFTER_KB` 後，同一題查過知識庫就不能再上網查；網址來源限制要求原樣比對，模型改寫網址（例如補上結尾斜線）也會被拒；網域白名單只檢查初始網址，轉址目的地不受限制。
- **已知風險**：自訂 API 與 MCP 工具的結果雖包上不可信標記，但不列入網址來源與引用編號，其出站請求不在本決策的限制範圍內。

### 升級與回退

- **升級**：在 `.env` 加入 `RRF_K`、`RERANK_RELEVANCE_THRESHOLD`、`WEB_FETCH_ALLOWED_DOMAINS`、`BLOCK_WEB_TOOLS_AFTER_KB`、`DOMAIN_PROFILE_PATH` 後再啟動。舊的 `HYBRID_ALPHA`、`NORMALIZATION`、`FINAL_THRESHOLD` 會被忽略。首次啟動時既有 BM25 索引沒有斷詞簽章，會自動依資料庫片段重建 BM25，向量不需重算。
- **回退**：退回舊版程式前先刪除 `BM25_INDEX_DIR` 目錄，舊版啟動時會依資料庫重建 BM25。若不刪除，舊版會用未轉小寫的查詢比對已轉小寫的索引，含大寫字母的詞項（如 `MES`）將對不到。
